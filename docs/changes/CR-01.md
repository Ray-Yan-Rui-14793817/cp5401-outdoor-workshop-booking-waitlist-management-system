## Problem and requested change

In V1.0, an eligible participant who tries to book a full workshop gets FULL and must check availability again after a cancellation. Add an explicit per-workshop waitlist so an eligible participant can queue for a full workshop. An effective pre-cutoff cancellation of a confirmed booking should give the released place to the earliest current waiter in that workshop. Participants need to see whether they are waiting or confirmed and learn about a promotion in time for the booking decision that matters to them.

## Time policy

S is the timezone-aware workshop start. C is S minus 24 elapsed hours. t is fresh trusted server decision time. Display the start and cutoff separately in Asia/Singapore.

| Operation | t < C | C <= t < S | t >= S |
|---|---|---|---|
| Create proposed workshop | Allowed with valid fields and lead greater than 24 hours | Reject | Reject |
| Book, effective confirmed cancellation, explicit Join | Apply existing and new business rules | REGISTRATION_CLOSED | REGISTRATION_CLOSED |
| FIFO promotion | Only as part of one effective confirmed cancellation | Closed | Closed |
| Owner withdrawal of an active waiter | Allowed | Allowed | WORKSHOP_STARTED |
| Scoped reads and repeats of owned CANCELLED IDs | Allowed as scoped reads or no-ops | Same | Same |

The UI reads current session state and trusted time again on submission. A display captured before C or S does not extend an action window. There is no timer, refresh or background promotion. This table applies to effective actions after the actor, ownership and action-state checks below.

## Approved action-state decision D-01

An older Withdraw control can refer to an ID that has since been promoted. Preserve separate action intent at the business boundary. The Withdraw entry expects WAITLISTED and the existing confirmed cancellation entry expects CONFIRMED. The expected state is fixed by the operation's entry point. Loading the record by ID does not convert one action into the other. A small shared helper is an implementation option.

| Precedence for the submitted registration action | Approved result |
|---|---|
| Invalid actor or disallowed role | Retain INVALID_ACTOR or FORBIDDEN. |
| Valid role with unknown ID or a record owned by another participant | Retain UNKNOWN_REGISTRATION or FORBIDDEN respectively, before disclosing current status. |
| Known, owned CANCELLED record | Return ALREADY_CANCELLED on either route before checking time or action mismatch. |
| Owned active record with a missing referenced workshop | Retain UNKNOWN_WORKSHOP. |
| Known, owned active record whose status does not match the action | Return STATUS_CHANGED and retain the entire state, including counters. Prompt the participant to refresh and review the current status. This applies before, at and after C or S. |
| Known, owned active record that matches the action | Apply the existing usable-clock validation and the deadline for that action. A late matching cancellation is REGISTRATION_CLOSED. A late matching withdrawal at or after S is WORKSHOP_STARTED. |

D-01 remains approved for the candidate. The mismatch leaves the record in its current state. [CRV-01](CR-01-verification-plan.md#new-and-affected-test-mapping) defines the future verification of precedence and state preservation. The approved baseline policy remains the source for valid actions.

## Accepted implementation constraints

1. Apply the approved D-01 precedence and the STATUS_CHANGED outcome at each affected registration action boundary.
2. Retain the original four identities and add Leo and Willy to the default state. For synthetic FIFO tests, add Alpha and Zulu as valid distinct participants in that fixture's state. Resolve actors against the fixture containing them and match stored owner IDs. Run the Leo/Willy multi-waiter journey in an ordinary six-user browser session. Use independent clocks in automated boundary tests and label walkthroughs used for human validation.
3. Use the existing single-session model with a simple per-workshop sequence and an optional historical sequence field on a registration. FIFO uses `queue_seq` only. Issued sequences are unique within a workshop. Names, displayed positions, timestamps and list order have no bearing on priority. Positions are derived from active waiting rows, so they can change without renumbering sequences. Details of field placement and the smallest safe copy path are reviewed against the actual patch later.

## Scope and delivery boundaries

The assessed change is the waitlist and automatic promotion. Keep the three core files, existing dependency locks, single-job Actions and the accepted V1.0 tests. The original identities, creation validation, seeded workshop and registration data, counters and no-waiter fixtures remain the baseline. Schedule-conflict prevention is reserved for L10 CR-02 and BR-17. Excluded are real authentication, notification, attendance tracking, durable or cross-session persistence, shared concurrency, capacity edits and a confirmed-roster override.

The published baseline, tag, Stage 5 records, local V1.0 ZIP and existing Streamlit deployment stay intact. The author's L7 ACCEPT_LOOP approved planning. The author separately directed L8 implementation and the P2 amendment. The P2 candidate branch starts from the accepted P1, which descends from M. Link implementation, dispositions, the justified PR decision, exact-SHA CI and eventual V1.1 release in subsequent work. The project author performs all actual merges and deployment fast-forwards.
